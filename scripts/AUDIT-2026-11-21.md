### Design and conventions

**D1: set -e is the failure mechanism, but bash suppresses it in conditionals (Design, resilience; repeat finding; MEDIUM; mg4).**
Earlier audit tasks n33, q33 and x33 added strict mode as the fix for silent
failures. Bash ignores set -e inside functions called from `if`, `!`, `&&`
or `||`. B1 comes from that: q33's `if ! download_assets_for_account`
disabled it. B4 is the reverse case, set -e aborting on an expected EOF.
`shellcheck -o check-set-e-suppressed` flags 86 call sites. Most are
harmless predicates; the risky ones are side-effecting functions with no
explicit checks. Nothing enforces the rule: no single test runner exists, and
audit-due, harness-watch, screenshot, tmux-cycle-a-session and home-backup
are never shellchecked by any test. Remedy (lever): add a test runner that
shellchecks every script, add `.shellcheckrc` enabling the check, and for each
site either add an explicit status check or an inline disable with a reason.
Trade-off: many disables on predicates.

**D2: tests assert on source text instead of behaviour (Design, test quality; MEDIUM; ng4).**
`tests/immich-export.sh` has 48 `grep -q ... "$IMMICH_EXPORT"` assertions, and
about 110 exist across the suite. They pass whatever the code does. B1, B2
and B3 all pass the current suite. `tests/immich-upload.sh` never calls
`upload_file` or `main`; it builds its own curl command. Remedy: replace
these with entry-point tests that put fake binaries on PATH, and keep only
real structural rules.

**D3: stabilize-video's delete gate is coded twice (Design, DRY/KISS; MEDIUM; og4).**
The verify loop in `_encode_verify_delete` (370-434) and main's
inspect-then-delete loop (552-601) both encode "decode OK + sanity + identity
recheck before rm", and they recheck identity in different ways. The file had
11 commits since `audit/2026-10-03`, three of them review follow-ups on this
logic. Both functions are about 134 lines. Remedy: shared verify and delete
helpers, pinned by `stabilize-video-e2e`.

**C1: functions over 50 lines (Convention, user rule in `~/.claude/CLAUDE.md`; MEDIUM; pg4).**
14 functions outside stabilize-video exceed the limit. The largest are
`immich-export` `download_assets` (111), `quicklog/drain` main (103) and
`wol-f3s` main (86). The failure paths behind B1 and B3 sit inside these
long bodies.

## Overall assessment

Defect risk is moderate. No critical bugs; the earlier audit's hardening
(path safety, pinned SSH keys, atomic encodes, kept sources) holds up. The
remaining defects share one premise: failures are assumed to propagate
through `set -euo pipefail`. In practice set -e is off in conditional call
trees, and nothing checks the exit status of the photo tools. The test
suite looks large but leans on grepping the scripts' source, so exactly
these exit-status paths are unpinned. Structurally, the ops scripts are well
factored around the shared `lib/f3s-hosts.sh` and `lib/immich.sh`. The main
cost is long functions, plus stabilize-video's defensive layers, which grew
by accretion and now duplicate the delete policy. There is a tension between
DRY and local explicitness: explicit `|| return` checks add lines to
functions already over the 50-line rule. So the pragmatic order is: fix the
exit-status bugs with entry-point tests first, then add the runner and lint
(D1), then split the long functions (C1, D3) under those tests.
