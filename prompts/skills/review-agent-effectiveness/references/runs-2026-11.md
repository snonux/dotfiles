# Runs of the card workflow, 2026-11-21

Read this when judging whether a later change to the cards or the `ask` CLI
made things better or worse. The pre-change numbers are in
[baseline-2026-11.md](baseline-2026-11.md).

## First live run of the cards (2026-11-21)

A four-task Go test project, run with Sonnet sub-agents and `ask` v0.45.1.
An orchestrator followed the orchestrator card; three workers and two
reviewers got only their pasted card. Then one Sonnet agent ran
`work-on-tasks` alone, with no sub-agents, for the last two tasks.

| Check | Result |
|---|---|
| Tasks finished / parked correctly | 4 of 4 finished; the task that needed a decision was parked with a one-line question, and the run stopped while its dependent waited |
| Tool errors across 6 agents | 0 |
| Skill files read by workers and reviewers | none beyond the pasted card (reviewers ran `crap-check.sh`) |
| Skill files read by the solo agent | `work-on-tasks/SKILL.md`, the three cards, `8-blocked-and-handoff.md` |
| `ask info` calls per agent and task | 1 |
| Workers running `ask start`, `ask done`, push, or sub-agents; `git add -A` | none |
| `Red first:` annotation and commit message with why, what, proof | every task |
| `ask` inside a linked worktree | worked (one worker ran there) |
| Review rounds | 1 per task, all PASS |
| Time per task | 13 to 34 seconds per worker, 12 to 17 per reviewer |

One slip: a worker ran `-race` three times where the card said once. Rule 4
of the worker card was reworded afterwards ("While working: only your own
tests, no `-race`"). The harness's refusals of complex commands inside
harness-isolated worktrees were not exercised, because the test worktree was
created by hand outside the session's repository.

## First real run (2026-11-21, Opus 5.5 at medium effort)

24 tasks across six repositories in one orchestrated run: a script audit and
its 16 fix tasks with gate and tagging, a multi-repository chore, two small
features, a production investigation with deployment, and a
documentation-picture retake. 24 workers and 25 reviewers, each given only
its pasted card plus task-specific notes; 17 workers ran in harness-isolated
worktrees.

| Measure | History | This run |
|---|---|---|
| Tool error rate, worktree workers | 5.1% | 3.2% |
| Commands refused inside worktrees | at least 5 per agent | 7 in 1,450 tool calls (17 agents) |
| Workers that ran `ask done`, `ask start`, pushed, spawned agents, or used `git add -A` | 61 / 41 / 171 / 41 / 189 | 0 for each |
| `ask info` calls per worker, median | 2 to 4 | 1 |
| Annotations per worker, median | 4 to 7 | 2 |
| Workers reading skill files beyond the card | most Codex agents | 3 of 24, only where the task named a file |
| Review rounds | up to 9 | 25 reviews for 22 items; 2 items needed round two; none a third |
| Worker / reviewer active time, median | not comparable | 4.4 / 1.4 minutes |

What the reviews caught: a new lint warning, a missing failure-path test,
coverage lost by deleting two checks, wrong captions. What workers found
beyond their task: a second cause of a symptom, `mv -n` exiting 0 when it
declines, a data-loss path in a video script, a coprocess race. Each became
its own task or was fixed in place and reviewed.

Problems the run exposed, and what changed because of them:

- `ask list start.any:` hid a started task with a later due date: fixed in
  `ask` v0.45.3, which also shows the due date in `ask info`.
- The reviewer card assumed a code diff; audits, chores, deployments and
  refactors needed the same extra sentences every time: now in the card.
- Lint was not named in either card, and one fix introduced a lint warning:
  both cards now name it.
- A reviewer's suggestion to delete two "duplicate" checks was passed on
  unverified and lost coverage: the completion reference now says such
  suggestions are never cheap.
- The audit's hotspot ranking for Bash could not be reproduced from the
  report: the exact command must now be recorded.
- Audit findings needed `+auto` and late findings needed adding to the gate
  by hand: both are now in the audit's task reference.
- Tasks in other repositories needed a note about where the shell starts,
  and build-heavy work had to be held while other sessions loaded the
  machine: both are now in the orchestration reference.

Still open as proposals: a one-line `ask status` for the orchestrator's
status line; telling workers to read the card file instead of pasting it,
which would save orchestrator output but is unproven for agents that skip
files; renaming the misspelled `taskwamurai` project.
