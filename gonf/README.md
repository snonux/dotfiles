# gonf recipes

gonf module for this repo. Pinned: `github.com/snonux/gonf v0.25.0` (`go.mod`), supporting plan schemas through 31 for the migrated DSL helpers and destination policies. Task list: [../README.md](../README.md#tasks).

## Layout

```text
cmd/gonf/main.go   registers HomeTasks (home_*), aliases and the explicit unprivileged "home" aggregate; cli.Main()
home/home.go       HomeTasks: unprivileged home resources, including the upload timer
paths/paths.go     controller source roots: Dot, DotPrivate, NotesPrompts
Magefile.go        deps, build
```

Source roots, read on the controller when the plan is recorded:

| Func | Root |
|---|---|
| `paths.Dot(rel)` | `$GONF_DOTFILES_ROOT` (absolute, else startup panic) or `~/git/dotfiles` |
| `paths.DotPrivate(rel)` | `~/git/conf_private/dotfiles` |
| `paths.NotesPrompts(rel)` | `~/Notes/Prompts` |

Destination paths use `DestHome(...)` (recorded as `${HOME}/...`, expanded on the destination). Controller sources use `paths.Dot("x")`, `paths.DotPrivate("x")` and `paths.NotesPrompts("x")` (built with `Home`, read where gonf runs). Symlink targets into the destination's own checkout use `paths.DestDot("x")` and `paths.DestNotesPrompts("x")`.

## Adding a task

Add a method to `HomeTasks` in `home/home.go`, with a doc comment, then run `go generate ./...` (it writes the `-list` description into `desc_gen.go` from the comment's first sentence: "Installs ~/.config/foo"):

```go
func (HomeTasks) OptsFoo() TaskOptions { return TaskOptions{WhenLinux()} } // optional guard

// Foo installs ~/.config/foo.
func (HomeTasks) Foo() {
	config("foo") // SyncDir(DestHome(".config/foo"), paths.Dot("foo/*"))
}
```

A hand-written `DescFoo() string` still wins over the generated one.

- Name is prefix + snake_case of the method: `FishCompletions` -> `home_fish_completions`. The prefix is the package name (gonf derives `home.HomeTasks` -> `home_`), so `main.go` passes no `WithPrefix`. Add new unprivileged home tasks to the explicit `home` aggregate in `main.go` when they belong in the standard deployment.
- Guards (`WhenLinux()`, `WhenDarwin()`, `WhenBSD()`, `WhenOS(...)`, `WhenNotOS(...)`, `WhenProfile(...)`) must be serializable; they run on the destination.
- Optional controller-side sources: guard with `OptionalControllerDir(dir, task)`. Missing dir skips the task; an unreadable directory or wrong file type reports a declaration error and refuses the plan. Destination-side existence: `WhenPathExists`.
- Resources used here: `SyncDir` (`WithPrune`, `WithFileMode`), `InstallFile` (`WithMode`), `Symlink`, `SymlinkMap`, `Dir`/`EnsureDir` (`WithSource` for a tree, `WithExclude` for omissions), `GitGlobal`, `SystemdUnits`, `SystemdTimer`, `Packages`/`NoPackage`.
- Root-owned configuration and package installation belong in `~/git/conf/gonf/workstation`, not this module.
- Renamed task: keep the old name as `Alias(old, desc, new)` in `main.go` (see `home_prompts`, `home_tmux_rocky`).

`home_systemd_user`: removes the legacy `home-backup` user timer on every Linux host (`NoSystemdTimer`). On hostname earth, raw `systemd-user/quicklog-drain.*` units are fanned into one change-gated user daemon-reload via `SystemdUnits` (the thin `quicklog-drain` wrapper and nested `scripts/quicklog/drain` are ordering dependencies of its timer only, so editing them does not reload), and `random-wallpaper` is generated by `SystemdTimer` (units mode 0644). `home_systemd_user` still declares the wrapper and nested drain explicitly so running that task alone installs both before activating the timer. `home_scripts` uses the tree-sync recipe below.

## Build and test

```sh
cd ~/git/dotfiles/gonf
GOWORK=off go build ./...
GOWORK=off go vet ./...
GOWORK=off go run ./cmd/gonf -list
GOWORK=off go run ./cmd/gonf -n home    # dry-run
mage          # = mage build: ./gonf binary
mage deps     # go mod download
```

`cmd/gonf/main_test.go` checks the recorded home and upload plans plus local CLI privilege preflight. Use `-list` and a dry-run for a local smoke check.

Bumping gonf: `go get github.com/snonux/gonf@vX.Y.Z && go mod tidy`. If a fresh tag is not on the proxy yet: `GOPROXY=direct GOSUMDB=off go mod tidy`.

## Running

Use `../gonf.sh <args>` (see [../README.md](../README.md#deploy)). It sets `GONF_DOTFILES_ROOT` only when run from a checkout other than `~/git/dotfiles`, and never resolves symlinks (FreeBSD `/home -> /usr/home`), since link targets in the plan would change. A built `./gonf` takes the same args.

Privileged `pkg_*` and `system_*` recipes now live in
`~/git/conf/gonf/workstation`, retaining their task names. Apply Fedora package
setup from conf with `./gonf.sh -privilege=sudo workstation` on earth/zen.
The hosts inventory has one owner in conf's `gonf/etchosts`; dotfiles keeps
only user configuration.

`home_goprecords_upload` remains a separate unprivileged task. Apply conf's
`system_uptimed` first on earth/zen, then run this repo's
`./gonf.sh home_goprecords_upload` to install the user client and timer.
The daemon prerequisite is a documented deployment step across repositories.

`home_aerc` is part of `home`, guarded to Linux and hostname earth. It deploys
`aerc/accounts.conf`, the pinned public Bridge certificate, `~/bin/aerc` (sets
`SSL_CERT_FILE`), `~/.protonbridge` (credential-file references), the disabled
local Bridge autostart entry, and `protonbridge-k3s-tunnel.service`. The user
service stays enabled and active; changes to its unit trigger daemon-reload
and restart. Deploy just this setup with `./gonf.sh home_aerc` from the repo root.

Prerequisites are `/usr/bin/aerc`, `/usr/bin/kubectl`, working f3s kube access,
and the Bridge-generated password in `~/.config/aerc/protonbridge-password`.
The password is provisioned separately using Bridge's `info` command; gonf
preserves its content and enforces 0600 when it exists, and never creates an
empty substitute or includes the password in a plan. The public certificate is
versioned as `aerc/protonbridge-ca-bundle.pem`: after a verified Bridge
certificate rotation, update that source and redeploy. Keep `~/bin` before
`/usr/bin` on PATH. aerc's other UI settings remain local.

## Tree sync beside flat sync

`SyncDir(dst, glob)` remains useful for flat config directories and matching raw unit files. To deploy nested production scripts as well, `home_scripts` now uses a source tree:

```go
scripts := Dir(DestHome("scripts"), WithSource(paths.Dot("scripts")),
    WithMode(0o700), WithFileMode(0o750), WithPrune,
    WithExclude("tests", "quicklog", "quicklog-drain-e2e"))
Dir(DestHome("scripts/quicklog"), WithSource(paths.Dot("scripts/quicklog")),
    WithMode(0o750), WithFileMode(0o750), WithPrune,
    WithExclude("e2e"), DependsOn(scripts))
NoFile(DestHome("scripts/quicklog-drain-e2e"))
```

The existing top-level scripts and nested `quicklog/drain` stay installed. The tree also installs `lib/f3s-hosts.sh`, `lib/immich.sh` and `lib/e2e-assert.sh`, which the production scripts and the previously deployed `taskwarrior-export-e2e` wrapper reference. Script files stay `0750`; the root stays `0700`. The main sync excludes `quicklog` entirely; the separate dependent sync keeps that directory at `0750` without changing its mode back and forth on every run. Other included subdirectories use `0700`.

`tests/` and `quicklog/e2e/` are never packaged. Exclusions preserve matching destination paths even with pruning, so the explicit `NoFile` still removes an already installed `quicklog-drain-e2e` wrapper. Other excluded destination paths remain unmanaged.
